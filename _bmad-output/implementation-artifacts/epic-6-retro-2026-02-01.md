## Challenges and Growth Areas

### 1. Edge Cases Caught in Review, Not During Development
**Issue:** Pagination bug and status validation gaps were caught in code review, not during initial development or testing.

**Impact:** Required rework and fixes after initial implementation.

**Root Cause:** Tests covered happy paths but missed edge cases (pagination with filters, invalid status transitions).

**Action Item:** Add "Edge Case Review" task to each story before testing phase.

**Team Quote:**
> Elena (Junior Dev): "The tests were passing because they didn't catch the pagination edge cases. I should have written more comprehensive tests initially."

### 2. "Optional" Task Labeling is Misleading
**Issue:** Task 8 in Story 6.2 was labeled "Optional" but proved essential for usable UX (sorting, search, keyboard shortcuts, CSV export).

**Impact:** Uncertainty about scope, all "optional" work actually completed.

**Root Cause:** Task labeled optional for story size management, but features were UX requirements.

**Action Item:** Re-evaluate "optional" labeling - if it impacts usability, it's not optional.

**Team Quote:**
> Alice (Product Owner): "I marked Task 8 as optional to keep the story manageable, but in hindsight, those features should have been in the original acceptance criteria."

### 3. Documentation Debt Accumulating
**Issue:** Two documentation tasks deferred from Story 6.1:
- OpenAPI spec updates for alert_records endpoints
- Architecture documentation updates for alert_records table

**Impact:** Documentation not in sync with implementation.

**Root Cause:** Tasks marked as deferred to appropriate phases, but no timeline for completion.

**Action Item:** Complete Epic 6 documentation before Epic 7 kickoff.

### 4. Architectural Decision: Client-Side vs Server-Side Filtering
**Issue:** Story 6.2 implemented client-side filtering/sorting (fetches all records, filters in memory) rather than server-side.

**Impact:** Works for current dataset size, but scalability implications unclear.

**Root Cause:** Chosen for simplicity and UX performance.

**Action Item:** Revisit this decision if alert records volume grows significantly.

## Key Insights

### 1. Code Review is Effective Safety Net
**Insight:** The code review process consistently catches real issues that would impact production. 12 fixes across 2 stories demonstrates value.

**Application:** Continue thorough review process. It's working.

### 2. Task Estimation Needs "Optional" Criteria Definition
**Insight:** "Optional" tasks are being mislabeled. Need clear criteria:
- Optional: Nice-to-have features that don't impact core usability
- Not Optional: Features required for usable product experience

**Application:** Alice will review story scoping before Epic 7 story creation.

### 3. Edge Cases Need Upfront Attention
**Insight:** Pagination, validation, and state transition edge cases are being missed in initial implementation.

**Application:** Add explicit "edge cases to consider" task to each story before testing phase.

### 4. Test Coverage Should Include Edge Cases From Start
**Insight:** Tests covering happy paths but missing edge cases leads to bugs caught in review.

**Application:** Dana proposes test-first approach for complex logic (TDD experiment in Epic 7).

### 5. Documentation Deferral Needs Timeline
**Insight:** Deferring documentation without clear completion timeline leads to debt accumulation.

**Application:** Set deadline for documentation completion (before Epic 7 kickoff).
