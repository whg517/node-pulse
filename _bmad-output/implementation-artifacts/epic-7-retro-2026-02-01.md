## Challenges and Growth Areas

### 1. Preparation Plan Was Skipped
**Issue:** Epic 6's retrospective explicitly recommended a 2-week preparation plan with research spikes (comparison algorithm, diagnosis engine, ECharts prototype, test scenarios). None of this preparation was done before starting Epic 7.

**Impact:** Discovered ECharts complexity (markPoint positioning) during Story 7.1 implementation, causing multiple hours of rework. Algorithm research completed during Story 7.4 development, not before.

**Root Cause:** No mechanism to enforce retro preparation recommendations. Action items lack tracking and follow-through.

**Action Item:** Enforce preparation plans for research-heavy epics; create action item tracker.

**Team Quote:**
> Kevin (Project Lead): "The Epic 6 retrospective was very clear about needing preparation, but we jumped straight into Epic 7 stories without doing those research spikes."

### 2. Action Item Follow-Through Poor
**Issue:** Epic 6 retrospective had 5 action items. Only 1 was partially addressed (edge case review). 4 were not done:
- Re-evaluate "optional" task labeling (not applicable - no optional tasks in Epic 7)
- Add edge case review task (partial - some stories did it, others didn't)
- Consider test-first approach (NOT DONE - didn't try TDD)
- Complete Epic 6 documentation (NOT DONE - still deferred)

**Impact:** Documentation debt accumulating. Process improvements not consistently applied. Retro commitments losing credibility.

**Root Cause:** No action item tracking mechanism. No weekly status checks. Retro items not added to sprint backlog.

**Action Item:** Improve action item follow-through with tracker and weekly reviews.

**Team Quote:**
> Kevin (Project Lead): "We completed 1 of 5 action items. That's poor follow-through. We need to take action items more seriously."

### 3. Documentation Debt Accumulating
**Issue:** Epic 6 Story 6.1 deferred 2 documentation items: OpenAPI spec updates, architecture documentation updates. Epic 7 added 2 new documentation needs: ECharts positioning pattern, statistical confidence calculation.

**Impact:** Documentation not in sync with implementation. Knowledge not captured for future reference.

**Root Cause:** Documentation deferred without clear completion timeline. No scheduled documentation blocks.

**Action Item:** Complete Epic 6 documentation before Epic 8; document Epic 7 patterns.

**Team Quote:**
> Alice (Product Owner): "We're deferring documentation without clear timelines. This is exactly the pattern Epic 6's retro warned against."

### 4. TDD Not Tried Despite Recommendation
**Issue:** Epic 6 retro recommended experimenting with test-first approach for complex logic (diagnostic engine). Epic 7 did not try TDD.

**Impact:** Complex logic (confidence calculation, problem type determination) implemented without tests first. Edge cases caught in code review, not during development.

**Root Cause:** Retro recommendation not enforced. No mechanism to ensure experiments are tried.

**Action Item:** Next complex feature must try test-first approach.

**Team Quote:**
> Dana (QA Engineer): "Epic 6's retro explicitly called for experimenting with TDD in Epic 7. But we didn't try it. This one disappoints me."

### 5. ECharts Complexity Discovered Late
**Issue:** Story 7.1's difference visualization (markPoints with ▲/▼ icons) required understanding ECharts coordinate system. This complexity was discovered during implementation, not during prototyping.

**Impact:** Elena spent several hours on markPoint positioning. Multiple iterations to get it right.

**Root Cause:** Epic 6 retro recommended ECharts proof-of-concept, but preparation was skipped.

**Action Item:** Prototype before committing to implementation for complex UI components.

**Team Quote:**
> Elena (Junior Dev): "I really struggled with the ECharts difference visualization. Getting the positioning right took multiple iterations. Lost several hours on that."
